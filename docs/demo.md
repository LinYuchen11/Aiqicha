# 功能演示说明

> 演示前先执行 `python scripts/init_db.py`，再 `python run.py`。默认进入 Mock 模式，无需 API Key；Embedding 默认档位为 `hash`（词面哈希向量，非语义 Embedding），保证「只装默认依赖」即可跑通。

## 一、5 分钟演示流程

| 步骤 | 页面 | 操作 | 应看到的结果 |
| --- | --- | --- | --- |
| 1 | 知识库管理 | 查看统计与文档列表 | 6 份模拟企业制度文档已完成解析、分块、向量化；显示实际 Embedding 档位与向量数 |
| 2 | 检索调试 | 输入「年假需要提前几天申请？」，选择混合检索，勾选重排序前后对比 | 召回文本块、向量分/关键词分/综合分、真实章节与原始片段、重排前后排名 |
| 3 | 智能助手 | 输入「公司电脑无法连接公司网络，帮我查询解决办法，如果无法解决就帮我创建工单」 | 意图识别为「多步骤综合任务」，展示检索建议、IT 服务工具结果、后续创建工单的提示；不会擅自建单 |
| 4 | 智能助手 | 输入「帮我创建工单，办公电脑无法上网，联系方式 13800000000」 | 生成待确认工单；未写库 |
| 5 | 智能助手 | 点击「确认创建」 | 真实写入 SQLite，返回工单编号；再到「Agent 工具管理」查看工单与调用日志 |
| 6 | 智能助手 | 输入「查询工单 IT-xxxx-xxxx 的状态」 | 调用工单状态查询工具，返回创建时间、类型、状态与处理说明 |
| 7 | 智能助手 | 先问「公司电脑如何申请软件安装权限？」，再追问「那如果是设计软件呢？」 | 第二轮结合上下文改写查询（resolved_query），检索到设计类软件相关条款 |
| 8 | 智能助手 | 输入「公司是否提供免费住房补贴？」 | 检索层三判据判定资料不足，明确告知、不编造制度 |
| 9 | RAG 评估中心 | 依次运行 **5 组实验** | 真实 Recall@K / MRR / 响应时间 / 答案-上下文一致性、Plotly 对比图、自动生成的结论；人工评估项显示「待人工评估」 |

## 二、第二轮可验证演示

| 演示项 | 操作 | 应看到的结果（均可复核） |
| --- | --- | --- |
| 切换 BGE 档 | 命令行执行 `python scripts/switch_embedding.py local`，重启后端 | 脚本输出「配置档位 / 实际档位 / 模型名称 / 维度」，并调用 `reconcile_vector_model()` 重建向量库，最后打印 `compatibility_status` 校验结果。若可选依赖或模型不可用，脚本明确打印「⚠️ 模型未生效，已降级」与降级原因、实际档位为 `hash（local 降级）`——这是如实反馈，不是失败 |
| 查看侧边栏实际 Embedding 模型/档位 | 打开前端任意页面看左侧栏 | 显示「Embedding：模型名称｜维度｜配置 X / 实际 Y」；非语义时额外显示「⚠️ 当前为词面哈希向量（非语义 Embedding），仅作离线备用；正式演示推荐 local / BAAI/bge-small-zh-v1.5」；模型不一致时显示红色错误提示。数据来自 `/api/health` 的「向量方案」与「向量库一致性」 |
| 运行 5 组实验 | RAG 评估中心依次运行 5 组，或命令行 `python scripts/run_evaluation.py` | 实验一~五全部有记录；实验四含「规则式重排序」并在 CrossEncoder 不可用时标注「未运行」；实验五含 hash 方案并在 BGE 不可用时标注「未运行、未生成任何指标」。报告 `docs/evaluation_report.md` 与界面一致，不出现虚构的模型数值 |
| 查看新增「答案-上下文一致性」指标 | 实验详情 / `docs/evaluation_report.md` 指标表 | 每个方案多出「答案-上下文一致性」列，指标说明明确它是「词面支撑率代理指标，不调用大模型，仅用于同测试集方案间对照」，不是语义忠实度分数 |
| 多工具连续执行 | 智能助手输入「先查一下 VPN 相关的 IT 服务，如果有对应服务，再帮我查询工单 IT-20261116-0001 的状态」 | 意图识别为 `multi_tool`；trace 中「工具执行」出现 2 次：`it_service_query` → `ticket_query`。第一步查到服务后才通过受控回边（`next_tool`）继续第二个工具；回答汇总两个工具的真实执行结果。若第一步没有匹配服务则只执行一个工具并如实说明 |
| 追问补答恢复 | 先说「帮我创建工单，办公电脑无法连接公司无线网络」，系统追问后**只回**「联系方式 13800000000」 | `intent_node` 依据 `pending_intent` 恢复「工单创建」意图，合并上一轮问题与补充信息，重新生成待确认工单；不会被判成 `unknown`，也不会直接写库 |
| 真实 DeepSeek 验证脚本 | 命令行执行 `python scripts/verify_deepseek.py` | 当前无 `.env` / `DEEPSEEK_API_KEY` 时应输出「**真实 DeepSeek API 未验证**」，8 项检查全部记为「未验证」、耗时「—」，并说明 `docs/deepseek_verification.md` 保持未验证模板、未写入模拟结果或虚构数值。若日后配置 Key，脚本才会对真实接口发起请求并把真实结果写入该报告 |

> 说明：本次环境没有 `.env` / DeepSeek Key；可选依赖 `sentence-transformers` / `torch` 安装超过 29 分钟无进展，已主动停止，因此 BGE 语义向量与 CrossEncoder 模型重排实验**均未运行**（`docs/evaluation_report.md` 的「未运行说明」为最终准绳，报告中未生成任何模型指标）；上表中「切换 BGE 档」演示的是**切换与重建链路是否如实反馈**（含降级情形），不声称 BGE 语义检索效果已跑出结果。

## 三、可验证的「真实」证据

- 来源引用：展开回答下方「知识来源」，文件名称、章节、页码、片段均来自 `vectors` 表真实记录。
- 工具执行：Agent 工具管理页「工具调用记录」含调用时间、参数、结果、状态、耗时，与 `tool_logs` 表一致；`integrate` 前还会经 `tool_guard.sanitize_tool_results` 校验来源。
- 数据持久化：重启前后端进程后，文档、会话、工单、日志、实验记录与 `embedding_meta` 指纹记录仍在。
- 评估数据：`docs/evaluation_report.md` 与实验记录均由 `scripts/run_evaluation.py` 真实运行生成，脚本可复跑；Agent 专项评估由 `scripts/run_agent_evaluation.py` 生成 `docs/agent_evaluation_report.md`。
- 决策来源：ChatResponse 的 `decision_source / plan_source / fallback` 区分本次是模型决策还是规则回退，可在 trace 与评估明细中查看。

## 四、切换到真实 DeepSeek 模型

1. 复制 `.env.example` 为 `.env`；
2. 填写 `DEEPSEEK_API_KEY`；
3. 保持 `LLM_MODE=auto`（或显式 `deepseek`）；
4. 重启后端；侧边栏提示变为「DeepSeek 真实模型运行」；
5. 重新提问，答案变为模型依据检索资料生成，并标注【来源 N】；
6. 运行 `python scripts/verify_deepseek.py` 完成 8 项真实验证。

注意：真实 API 调用会产生费用；本项目默认不调用任何外部接口。真实 API 调用失败时 `llm_mode` 会变为 `mock-fallback`，答案带「大模型调用失败」标注。

## 五、常见异常演示

| 异常 | 复现方式 | 预期反馈 |
| --- | --- | --- |
| 不支持的文件类型 | 上传 `.exe` | 「不支持的文件类型」中文提示 |
| 空文件 | 上传 0 字节 `.txt` | 「文件内容为空」 |
| 重复文件 | 重复上传同一文档 | 「重复文件」 |
| 文件过大 | 上传超过 `MAX_FILE_SIZE_MB` 的文件 | 「文件超过大小限制」 |
| 空知识库检索 | 删除全部文档后提问 | 明确告知知识库为空 / 资料不足 |
| 工具参数缺失 | 工具管理页不填工单编号直接调用 | 「工具参数不完整或非法」 |
| 未确认创建工单 | 工具管理页不勾选确认即调用 `ticket_create` | 「创建工单前必须由用户确认」，数据库零写入 |
| 会话隔离 | 新建另一个会话 | 看不到前一会话的历史消息 |
| 模型指纹不一致 | 手动改动 `EMBEDDING_MODE` 但不重建向量库 | 检索抛中文 `VectorError`，提示执行 `python scripts/rebuild_vectors.py`，绝不静默混用 |
